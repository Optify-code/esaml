## Changelog

All changes are in the `main` branch (`master` remains unchanged).

### v4.6.0-optify.2
Closes the atom exhaustion advisories. xmerl and esaml no longer make new atoms from an untrusted payload.
+   `esaml_util:scan_untrusted_xml/1` reads the payload with the SAX parser before xmerl parses it. Every element name, attribute name, prefix, local name and namespace URI must already be an atom. The fork makes the SAML, XML-DSig and XML-Enc names into atoms once. Any other name returns `{error, unknown_xml_name}`.
+   A processing instruction returns `{error, processing_instruction_not_allowed}`. An XML declaration with an encoding other than UTF-8 returns `{error, encoding_not_allowed}`.
+   `esaml:status_code_map/1` maps the SAML 2.0 status codes to the atoms that 4.6.0 gave them. Any other status code maps to `unknown`.
+   `esaml:common_attrib_map/1` returns an attribute name as a string when it is not an atom yet. samly turns every attribute key into a string, so its keys do not change.

### v4.6.0-optify.1
Optify fork of the Hex 4.6.0 package. It closes the esaml 4.6.0 XXE advisory.
+   `esaml_binding:decode_response/2` refuses a payload that holds a DOCTYPE, holds a NUL byte (UTF-16 or UCS-4), or is over 512 KB. A refused payload returns `{error, Reason}` and does not crash.
+   The redirect and POST bindings refuse compressed input over 512 KB before inflation. The inflation stops when the output passes 512 KB.
+   xmerl parses with `{allow_entities, false}` and a `fetch_fun` that refuses every external read. xmerl fatal errors return `{error, {bad_xml, Reason}}`.
+   `esaml_sp:decrypt_assertion/2` applies the same checks to the decrypted EncryptedAssertion plaintext. Malformed decrypted XML now returns `{error, {bad_xml, Reason}}`, not `{error, bad_assertion}`.
+   `esaml_sp` validators and `esaml_cowboy` pass a decode refusal through as `{error, Reason}`.
+   Requires an xmerl that knows the `allow_entities` option. Tested on OTP 27.3.4.19.

### v3.6.0

+   Fixed issued: #8 - LogoutRequest Validation Error
    Removed `ProtocolBinding` attribute from `LogoutRequest` and `LogoutResponse`.
    Made sure the `saml:Issuer` element is in proper sequence in the requests.
    Schema validation was failing for `LogoutRequest` and `LogoutResponse` without
    these fixes. Thanks to [mjcloutier](https://github.com/mjcloutier) for reporting
    this issue.

### v3.5.0

+   Erlang/OTP 21.0 support

### v3.4.0

+   Fixed issue: #4 - InResponseTo - make this available
    In case of SP initiated SSO, the auth response includes the original
    request ID. Make this available in the assertion subject esaml record.
    (as `in_response_to`). The IDP initiated requests don't include this.
    The `in_response_to` field is set to an empty string in that case.

### v3.3.0

+   `NameID` format can be passed as a parameter to `esaml_sp:generate_authn_request/3`.
    Deprecated `esaml_sp:generate_authn_request/2`. Pass in `undefined` as NameID format
    if you do not want to pass in `NameIDPolicy` in the authn request.

+   Passing `#esaml_subject{}` with the values returned in the authn response
    assertion subject. This is essential for sending appropriate `NameQualifier`,
    `SPNameQualifier` and `Format` values in the SLO logout request. Without these
    values, Shibboleth fails to match the SP session on the IdP side. Deprecated
    `esaml_sp:generate_logout_request/3`. It will be removed in a future release.
